Open Salamander: Plugins: WinSCP: Features

Directory Caching

WinSCP supports caching directory content. The caching can be configured per-session. To configure it, see Directories tab of Login dialog.

There are two caches. The first cache stores the file listing of already-visited directories. This cache is enabled by default and can be disabled by clearing the Cache visited remote directories checkbox. The cache is temporary; that is, it is not preserved between sessions.

The second cache stores information useful for changing directories, such as the existence of particular directories and canonical paths (useful only for the SFTP protocol, as SFTP servers do not necessarily follow Unix-style path handling). This cache is enabled by default and can be disabled by clearing the Cache directory changes checkbox. The cache can be permanent (enabled by default); that is, preserved between sessions. Note that the cache is specific to a particular user and host combination. You may need to disable it if you are running two servers on the same host with different path semantics. For the SCP protocol, the cache has no benefit without Cache visited remote directories also being enabled.

When both caches are enabled, previously visited directories can be opened without any data exchange with the server; that is, immediately.

The directory cache is updated whenever you perform any operation on the directory, such as a file transfer. If the directory is changed externally (not from WinSCP), you can use the Refresh command to reload the directory content and update the cache. Note that running a remote command purges the cache only for the current directory. If your command modifies other directories as well, you need to refresh them manually.
